**프로젝트 운영 방식**                                                                                   

  이 시스템은 **Obsidian = DB, md 파일 = 레코드, 링크 = 관계, Claude = 분석 엔진**으로 돌아갑니다.         

  ---             

  **1. 요구사항 생성 (RQ)**                                                                                

  **방법:** QuickAdd → "Creat Requirement" 선택 → num, func 입력

  예: 001, 로그인 → RQ-001-로그인.md 생성                                                              

  **핵심 규칙:**                                                                                           

  - 바로 RQ 만들지 말고 **00_Inbox에 먼저 메모** → 정리 후 RQ 생성

  - RQ는 **사용자 행동/기능 단위**로 생성 (버튼 단위 X, 화면 단위 X)                                       

  - 하나의 RQ = 하나의 사용자 행동 또는 기능 목표               

  **생성 후 채울 항목:** 상태, 담당자, 요구사항 설명, 정책, UI, API/데이터, 연결 문서                      

  ---                                                                                                  

  **2. 결정사항 관리 (DEC)**                                                                               

  **방법:** QuickAdd → "Creat Decision" 선택 → 번호, 제목 입력

  **언제 만드나:** **논쟁이 있었던 것만** 기록 (안 그러면 안 쓰게 됨)                                          

  **구조:**                                                                                                

  - 결정 내용 → 배경 → 검토한 옵션(장단점) → 최종 결정 이유 → 영향 범위 → 관련 회의

  예: "인증 방식을 JWT로 할지 세션으로 할지" 같은 논쟁이 있었을 때 DEC 생성

  ---             

  **3. 미팅 기반 요구사항 변경 (핵심 워크플로우)**                                                         

  이게 이 시스템의 **핵심 루프**입니다:

  **Step 1. 회의록 생성**                                                                                  

  QuickAdd → "Creat Meeting" → 날짜 기반 파일 생성 → 회의 내용 작성                                    

  **Step 2. Claude에 분석 요청**                                                                           

  회의 내용을 Claude에 넣고:                                                                           

  ▎ _"변경된 요구사항 / 신규 요구사항 / Decision 필요 항목 정리해줘"_

  Claude가 아래 형식으로 분석 결과를 줍니다:

  [Changes]                                                                                            

  - RQ-001: (뭐가 변경됨)

  [New Requirements]                                                                                   

  - RQ-XXX: (새 요구사항 요약)

  [Decisions Needed]

  - DEC-XXX: (결정이 필요한 이유)                                                                      

  [Impact Analysis]                                                                                    

  - RQ-001 → RQ-002, RQ-005에 영향

  **Step 3. 반영**

  - 기존 RQ 수정 (변경이력에 날짜와 내용 기록)                                                         

  - 신규 RQ 생성                                                                                       

  - DEC 생성                                                                                           

  - **[[링크]]****로 RQ ↔ DEC ↔ MEET 연결**

  **Step 4. 연결 확인**                                                                                    

  - Obsidian **그래프뷰**로 전체 연결 관계 시각적 확인                                                     

  - **백링크**로 특정 RQ에 영향을 준 회의/결정 추적

  ---             

  **4. 문서 간 연결 (추적성)**                                                                             

  ┌──────┬─────────┬────────────────────┐

  │ 문서 │ ID 형식 │     연결 대상      │                                                              

  ├──────┼─────────┼────────────────────┤

  │ RQ   │ RQ-001  │ 관련 RQ, DEC, MEET │                                                              

  ├──────┼─────────┼────────────────────┤

  │ DEC  │ DEC-001 │ 관련 RQ, MEET      │

  ├──────┼─────────┼────────────────────┤                                                              

  │ MEET │ 날짜    │ 관련 RQ, DEC       │

  └──────┴─────────┴────────────────────┘                                                              

  Obsidian [[RQ-001-로그인]] 식으로 링크하면 양방향 추적이 됩니다.                                     

  ---                                                                                                  

  **요약: 일상 사용 흐름**
 
 회의 발생 → MEET 작성 → Claude 분석 → RQ/DEC 생성·수정 → 링크 연결 → 그래프뷰 확인
